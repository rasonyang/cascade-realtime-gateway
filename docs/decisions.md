# Decisions

One line per decision, newest last. Format: `YYYY-MM-DD — <decision> (<why>)`.

- 2026-09-01 — Replies to the user are in Chinese per the user's harness language setting; code, comments, docs, commits and logs stay English per `CLAUDE.md`.
- 2026-09-01 — `session_defaults.audio.input.transcription` uses the GA nullable-object shape (no `enabled` field); `null` disables `conversation.item.input_audio_transcription.*` events, an object enables them. The internal ASR always runs for the ASR → LLM pipeline regardless. Exact field subset is frozen in Phase 2 (`PROTOCOL-VERIFY`).
- 2026-09-01 — `session_defaults.audio.output.speed` is in config with default `1.0`, validated against the currently documented GA range `[0.25, 1.5]`; re-verified when the Phase 2 profile is frozen.
- 2026-09-01 — `turn_detection` validation is type-specific: `threshold` / `prefix_padding_ms` / `silence_duration_ms` only for `server_vad`, `eagerness` only for `semantic_vad`; mixed shapes are rejected. Under `semantic_vad` the acoustic VAD (Phase 1) uses the `server_vad` defaults since GA exposes no tuning fields there.
- 2026-09-01 — Config load order: read → `{env.X}` expansion on the generic JSON tree (error names the field path) → strict decode (`DisallowUnknownFields`) over `DefaultConfig()` → mode-specific `turn_detection` defaults → `Validate`. Absent field = default; `"turn_detection": null` = manual mode.
- 2026-09-01 — `config.Validate(known ProviderLookup)` takes an injected lookup so `internal/config` never imports `internal/provider`; a nil lookup skips provider-name existence checks (Phase 0 only, registry wired in Phase 1).
- 2026-09-01 — WebSocket library: `github.com/coder/websocket`; added only when a phase needs it (Phase 2/3).
- 2026-09-01 — Phase 0 `cmd/cascade` with a valid config logs an allowlisted, redacted summary and exits 0; the HTTP/WebSocket server arrives in Phase 3.
- 2026-09-01 — `session` imports `config` and uses `config.SessionDefaults` directly as its immutable session snapshot and the `EvSessionUpdated` payload; `session.update` patches are validated with the same `SessionDefaults.Validate` as the config file (brief §7: "saving a translation layer").
- 2026-09-01 — Non-incremental TTS providers are downgraded to one `Synthesize` per sentence inside the pipeline's TTS stage (not inside each provider adapter): zero interface changes, and per-sentence audio ranges are exact for tier-2 truncation. Sentences are synthesized sequentially with no lookahead; revisit after Phase 4 latency measurements.
- 2026-09-01 — Commands carry an opaque `Tag` (`session.Meta`) echoed on `EvError` so the protocol layer can back-reference the client `event_id`; `provider.Factory` takes `(apiKey, options)`.
- 2026-09-01 — Inbound audio and commands stay on separate bounded queues, but every posted item carries a sequence number and the actor restores arrival order across the two queues (`append→commit` and `clear→append` behave as sent). Without this, `select` fairness could commit before earlier appends were applied.
- 2026-09-01 — ASR Final ↔ item mapping: Finals accumulate since the last commit; the first Final (or EndOfTurn) after a commit completes the committed item with everything accumulated. Audio that arrives between commit and the provider's flush may be attributed to the wrong item; accepted approximation.
- 2026-09-01 — Raw user PCM is not retained after commit (the ASR stream already received it live). If the Phase 2 profile supports `conversation.item.retrieve` with audio, storage is added then.
- 2026-09-01 — A committed item whose transcript never arrives and has no response waiting on it stays `in_progress` indefinitely; v1 adds no timeout for that case.
- 2026-09-01 — Algorithm constants kept as named constants rather than config (rule 7 covers queues, caps and timeouts): VAD frame 20 ms, hysteresis exit = 0.6 × entry, threshold→RMS scale 0.1, sentencer minimum 6 runes plus a small abbreviation list, semantic_vad eagerness → extra silence high 400 / medium 800 / low 1500 ms (auto = medium).
- 2026-09-01 — Outbound event stall handling lives in the Phase 3 server writer (`client_write_timeout`), not in the actor: `emit` blocks on a full outbound queue until ctx is cancelled; `EvSessionClosed` delivery waits at most `client_write_timeout`.
- 2026-09-01 — `response.cancel` with no active response or a foreign `response_id` is a silent no-op internally; whether the wire layer returns an error is settled in the Phase 2 profile (`PROTOCOL-VERIFY`).
- 2026-09-01 — Text-only responses do not open TTS at all; `ttsDone`/`audioFlushed` are considered satisfied. `audioFlushed` is set together with `ttsDone` because deltas and the done fact travel the same ordered channel.
- 2026-09-01 — Protocol profile approved (`docs/protocol-profile.md` §10). Protocol validation errors use only the officially attested codes `invalid_event` / `invalid_value` with `message` + `param`; Cascade runtime errors are `server_error` with Cascade codes. `conversation.item.created` and `rate_limits.updated` are never emitted. `voice` follows GA and is locked after the first output audio delta (session-owned `audioEmitted` flag).
- 2026-09-01 — Committed audio items are reported `in_progress` until their ASR final arrives, then `conversation.item.done` (GA reports `completed` immediately and transcribes asynchronously); Cascade's transcript gates the LLM, so the deferred `done` is the honest projection.
- 2026-09-01 — `conversation.item.truncate` beyond the generated audio is an error (`invalid_value`, `param: audio_end_ms`), never a clamp; the §5.5 "no trimming at or beyond total" invariant now applies only to `audio_end_ms == total`.
- 2026-09-01 — `Item.ClientID` / `ItemSpec.ClientID` carry the client-supplied item id opaquely through the session so the protocol layer's id table is filled from events alone; `EvResponseCreated` carries the effective modalities / voice / max tokens / metadata so the response object is echoed without guessing.
- 2026-09-01 — Inbound protocol validation walks the raw JSON object with per-event allow-lists (`internal/protocol/decode.go`) instead of `DisallowUnknownFields` structs, so every rejection can name the dotted `param` path and beta fields get a pointed message. The adapter resolves wire ids to session refs before posting, so unknown `item_id` / `response_id` / `previous_item_id` never reach the actor.
- 2026-09-01 — Golden traces normalize server ids to `<prefix:n>` in first-seen order (fixed-length id regex so `param: "item_id"` is not mistaken for an id); audio/transcript interleaving is covered by the causal-invariant tests only, as the brief requires. Regenerate with `go test ./internal/protocol -run TestGolden -update`.
- 2026-09-01 — Phase 2 acceptance item "text-only conversation with the official GA SDK or websocat" is deferred to the start of Phase 3: it needs the WebSocket server, and adding `coder/websocket` for a throwaway harness would widen Phase 2 scope.
- 2026-09-01 — Phase 3 server: one goroutine trio per connection (handler read loop, event pump, single writer). The read loop uses its own context so a session-context cancellation (timeout, shutdown, fatal error) lets the writer send queued frames and the close frame before reads stop; the writer's per-frame timeout is `client_write_timeout` from a background context for the same reason. WebSocket close codes: 1000 (client close / `session_timeout` reason), 1001 `shutting_down`, 1011 with the Cascade code for fatal errors, 1009 by the library when `client_max_message_bytes` is exceeded.
- 2026-09-01 — `websocket.Accept` skips the Origin check (`InsecureSkipVerify`): the endpoint is gated by the Bearer token, which browsers cannot attach cross-origin, so an Origin allow-list would only break non-browser clients.
- 2026-09-01 — `max_sessions` is enforced before the upgrade with HTTP 503 (JSON `server_error` body); a rejected connection never creates a session. `session_timeout` bounds the session context; the session reports `CloseSessionTimeout` from the deadline cause.
- 2026-09-01 — No shutdown timeout config: `Server.Shutdown` ends every session and waits; session cleanup is bounded by `client_write_timeout` and the close handshake by the library's 5 s, so `main` passes `2 × client_write_timeout` as the shutdown deadline.
- 2026-09-01 — Cascade serves plain `ws://`; TLS belongs to a terminator in front of it. The official `openai-node` v7.8.0 `OpenAIRealtimeWS` client refuses anything but `wss:`, so the manual Phase 2/3 acceptance ran through a throwaway self-signed TLS reverse proxy (scratchpad only) with `rejectUnauthorized: false`; it completed a text conversation with no beta header. The deferred Phase 2 acceptance item is therefore closed.
- 2026-09-01 — Phase 4 providers: `openai` LLM (Chat Completions SSE, `stream_options.include_usage`, `max_completion_tokens`, instructions as a `system` message), `openai` TTS (`/audio/speech` with `response_format: "pcm"` = 24 kHz 16-bit LE, one request per sentence, `IncrementalText=false`), `deepgram` ASR (`/v1/listen` linear16/24000, `interim_results`, `punctuate`, `endpointing`, `utterance_end_ms`; `Authorization: Token`). Per-provider timeouts live in the provider `options` block (`request_timeout`, `stream_idle_timeout`, `connect_timeout`, `finalize_timeout`, `keepalive_interval`) with defaults in each package.
- 2026-09-01 — Deepgram documents that the `from_finalize` result after `Finalize` is not guaranteed; the adapter synthesizes `EndOfTurn` after `finalize_timeout` (default 1.5 s) so the ASRStream contract ("Finalize guarantees a Final or EndOfTurn") holds. Empty `is_final` results are ignored unless they are the `from_finalize` reply.
- 2026-09-01 — Providers report lifecycle facts (`… stream opened/closed`, `reason`, `lifetime_ms`) at Debug level through `slog.Default()`; `cmd/cascade` installs the redacting logger as default. The e2e test captures these records to prove interrupt cleanup timing.
- 2026-09-01 — Real-provider e2e (`-tags e2e`, `internal/server/e2e_test.go`) synthesizes the user's speech with the real OpenAI TTS, runs one server_vad turn, then two interrupts (at first audio delta → TTS in flight; at first transcript delta → LLM in flight) and a disconnect. Measured 2026-09-01 with gpt-5-nano: commit→ASR final 0.9 s; tts/llm/deepgram streams closed 0–1 ms after cancel/disconnect. A pause inside one utterance splits the turn under server VAD (as with OpenAI), so the e2e widens `silence_duration_ms` to 800 and tolerates an intermediate cancelled response.
- 2026-09-01 — The commit → ASR Final latency is measured in the session (`transcript final` log with `commit_to_final_ms`); Phase 5 exports it as a metric.
- 2026-09-01 — Phase 5 observability: OTLP/HTTP exporters (`observability.otel_endpoint` = `host:port`, insecure; empty = no-op providers so session code never branches). Spans: `session` → `response` → `llm` / `tts`; the pipeline ctx derives from the response span so provider work is attributed without any provider instrumentation; no frame-level spans. Metrics (histograms in ms): `cascade.asr.first_transcript_ms` (speech start → first partial), `cascade.asr.final_transcript_ms` (speech stop → final), `cascade.asr.commit_to_final_ms`, `cascade.llm.ttft_ms` (pipeline start → first text delta), `cascade.tts.first_audio_ms` (first sentence handed to TTS → first audio delta, via the internal `pipeTTSStart` fact), `cascade.e2e_ms` (commit — or response.create for text turns — → first output delta), `cascade.interrupt_ms` (speech start / cancel command → response.done{cancelled}); counters `cascade.provider.errors{cascade.provider}`, `cascade.sessions.ended{cascade.reason}`, up-down `cascade.sessions.active`. In manual mode the commit stands in for speech start/stop.
- 2026-09-01 — Metric export interval is the SDK default (60 s) and spans are batched; `cmd/cascade` flushes both on shutdown, bounded by `client_write_timeout`. No new config fields.
- 2026-09-01 — Frame-level logging stays off: nothing logs per audio frame or per delta; provider lifecycle logs are Debug-level, one per stream.
- 2026-09-01 — `providers.llm.options.reasoning_effort` (openai) is passed through verbatim and omitted when empty: OpenAI documents that supported values vary by model (verified: `gpt-5-nano` rejects `"none"` and accepts `"minimal"`; non-reasoning models reject the field), so Cascade sets no default and validates nothing beyond "string".
- 2026-09-01 — `hack/sdkcheck/` keeps the official-SDK manual check (node scripts, mock config, self-signed TLS terminator in the main module); binaries, `node_modules/`, logs and pids are git-ignored.
- 2026-09-01 — Latency diagnostics kept in the tree: one Debug log per synthesized sentence (`tts sentence`: chars, audio_ms, first_audio_ms, total_ms), Deepgram `finalize satisfied` / `timed out` round-trip logs, and the e2e's in-memory-exporter profile (`PROFILE` lines: awaiting ASR final, LLM TTFT, first-sentence wait, TTS first audio; `PROFILE2`: a three-sentence answer to check end-to-end streaming). `CASCADE_E2E_TTS_MODEL` overrides the TTS model. First measurement (gpt-4o-mini + tts-1): e2e 5.9 s = ASR final wait 1.45 s + LLM TTFT 1.23 s + TTS first audio 3.19 s, with 0.6–1.1 s TLS handshakes on this network path inside the provider numbers.
- 2026-09-01 — Qwen / DashScope providers (`internal/provider/qwen`, all three registered as `"qwen"`) target the Model Studio host `llm-REDACTED.cn-beijing.maas.aliyuncs.com`, which is the package default and overridable per provider (`options.base_url` for the LLM, `options.url` for ASR/TTS). LLM: OpenAI-compatible SSE under `/compatible-mode/v1` (verified: `/v1` is 404), `max_tokens` (not `max_completion_tokens`), instructions as a `system` message. ASR and TTS share the duplex WebSocket `/api-ws/v1/inference` with `Authorization: bearer …` (lowercase scheme) and `X-DashScope-DataInspection: enable`.
- 2026-09-01 — `enable_thinking: false` is always sent on the Qwen chat request and is not configurable. Verified against the live endpoint: with the field absent or true, `qwen3.6-flash` streams `delta.reasoning_content` before any answer text. The chunk struct has no field for `reasoning_content`, so reasoning is dropped at decode rather than filtered later.
- 2026-09-01 — Qwen ASR runs one recognition task per turn on one session-scoped connection: `Finalize()` sends `finish-task`, the final transcript and `task-finished` follow, and the writer immediately starts the next task with a fresh `task_id` on the same socket. Measured on the live endpoint: `finish-task` flushes the final in 250–450 ms, versus ~940 ms for the model's own end-of-utterance judgement, and the task restart costs ~25 ms. Audio that arrives while a task is restarting waits in the existing bounded queue, so nothing is sent before `task-started` and nothing is dropped. If `task-finished` does not arrive within `finalize_timeout` (default 3 s) the stream synthesizes `EndOfTurn` and restarts the task, so the ASRStream contract holds either way. `parameters.language_hints` carries `ASRConfig.Language`; the service resamples 24 kHz input to its own 16 kHz internally.
- 2026-09-01 — Qwen TTS declares `IncrementalText: true` (`continue-task` per sentence under one `task_id`) and `Alignment: false`: the service reports sentence boundaries but always leaves the per-word timing array empty, so truncation stays at the proportional tier.
- 2026-09-01 — Qwen TTS flush nudge: the service holds a completed sentence unsynthesized until further input arrives, so in a cascaded pipeline the first audio frame waits for the LLM's *next* sentence. Measured with a deliberate gap after one sentence: first audio at 0.25 s with no gap, 0.32 s at 100 ms, 0.59 s at 300 ms, 1.05 s at 800 ms — the gap is paid in full. Splitting the sentence across two `continue-task` frames does not help, but a whitespace-only `continue-task` after it does: 0.25 s regardless of the gap. The writer therefore sends one space after a sentence when nothing else is queued. Verified byte-identical spoken content (audio transcribed back through the ASR) with ~640 ms tighter inter-sentence pauses. It leans on undocumented behavior, so `options.no_flush_nudge` turns it off; with it off the cost is the gap, with it on and the behavior gone the cost is one tiny frame per sentence.
- 2026-09-01 — Qwen TTS voices are the `long…` family, not the Qwen-TTS names: `Cherry`, `Ethan`, `longxiaochun` and the other CosyVoice v1 names are rejected with `InvalidParameter`. `longanlingxi` is the package default and `config.qwen.example.json` sets `session_defaults.audio.output.voice` to it, because the repo-wide default `"alloy"` would fail the task outright. `parameters.rate` carries `TTSConfig.Speed`.
- 2026-09-01 — Opt-in real-endpoint checks are split in two: `internal/provider/qwen/real_test.go` (`-tags qwenreal`) validates behavior — streaming, transcript accuracy, two turns on one ASR connection, the full ASR → LLM → TTS chain — and `hack/qwenbench` measures latency and writes the before/after report in `docs/qwen-latency.md`. Both read `ALIYUN_API_KEY` and never log it.
- 2026-09-01 — Phase 6 splits configuration by lifetime: the config file keeps only what is fixed for the process (`listen`, `auth.api_key`, `auth.admin_api_key`, `admin.listen`, `admin.state_file`, `limits`, `observability`, optional `bootstrap`); provider instances, profiles and `settings` become runtime configuration owned by `/admin/v1`. The `providers` and `session_defaults` blocks are gone from the config file — the same content now lives under `bootstrap`, which seeds the state file on a first start only.
- 2026-09-01 — Runtime configuration is one immutable `config.RuntimeConfig` behind an `atomic.Pointer` in `internal/admin` (lock-free reads for every new connection), writes serialized by a mutex, persisted to one JSON state file (temp in the same directory → `chmod 0600` → write → fsync → rename → best-effort directory fsync). Every write is `clone → apply → validate whole → build providers → persist → swap`; persistence failure returns 500 and leaves both memory and the file untouched, so the file is never ahead of memory and memory is never ahead of the file.
- 2026-09-01 — A profile's JSON shape is flat (`instructions`, `temperature`, `max_output_tokens`, `output_modalities`, `voice`, `speed`, `asr_language`, `asr_model`, `transcription`, `turn_detection`) rather than the GA session object: it is the Admin API's resource model and is what an operator reads and writes. `Profile.SessionDefaults()` projects it onto the existing GA-shaped `config.SessionDefaults` the session and protocol layers already consume, so no protocol code changed and the Phase 2–5 golden traces are byte-identical. Audio formats stay fixed constants and are not exposed in a profile. Validation is shared, not duplicated: `validateModalities` / `validateSpeed` / `validateMaxOutputTokens` / `TurnDetection.validate` are called from both `Profile.Validate` and `SessionDefaults.Validate`, each with its own field-path prefix.
- 2026-09-01 — `asr_language` / `asr_model` are profile fields and the single source of truth for the ASR stream; `transcription` keeps only its GA role (nullable toggle for the `conversation.item.input_audio_transcription.*` events, plus `prompt`), and `transcription.language` / `.model` inside a profile are rejected with a field error pointing at `asr_language` / `asr_model`. The projection copies the two knobs into the echoed `transcription` object so the session snapshot the client sees reports what is actually in force. `session.update` is unchanged and gains no fields; as before, it cannot retune a live ASR stream.
- 2026-09-01 — `temperature` lives on the profile, not in `SessionDefaults`: GA has no session-level `temperature` and `CLAUDE.md` forbids inventing `session.update` fields. It reaches the LLM as `provider.ChatRequest.Temperature *float64` (a pointer because 0 is a meaningful value); the openai and qwen adapters omit the field when it is nil. `Profile.Temperature` is itself `*float64` and unset by default rather than 0.8: Cascade never sent a temperature before Phase 6, and OpenAI's reasoning models (o-series, gpt-5 family — the documented e2e path) reject the parameter, so a default would have silently broken existing setups.
- 2026-09-01 — `{env.NAME}` expansion skips the top-level `bootstrap` block: the seed is runtime configuration and the state file must store the placeholder, not the resolved secret. Expansion happens once per provider build (`config.ExpandEnv`), so an unset variable is reported as a field error at write or startup time, never written to disk.
- 2026-09-01 — Secrets over the API: `GET` always returns `"***"`, `PUT` with `"***"` keeps the stored secret for that instance name (and is a 400 on an instance that does not exist yet, since there is nothing to keep). Admin writes log method/path/resource/status/`X-Request-ID` at INFO and never the body.
- 2026-09-01 — Delete semantics distinguish 404 (no such resource) from 409 (still referenced: a provider named by a profile, or the profile `settings.default_profile` points at). Validation alone would report these as 400 with a dangling reference; the reference check runs first so the status matches the cause.
- 2026-09-01 — Providers are built under the write lock and stored in the snapshot, one instance per (role, instance name) pair actually referenced by a profile — an instance has no role until a profile gives it one. Provider construction is therefore part of validation: an unparseable `options` block is a 400 naming `providers.<name>.options`, which is where provider-specific validation stays.
- 2026-09-01 — `server.Options.Providers` is replaced by `server.Resolver` (`Resolve() (admin.Runtime, error)`), implemented by `*admin.Store`; the snapshot is taken once per connection before the WebSocket upgrade, so "no default profile" is an HTTP 503 rather than a close frame, and an Admin write can never disturb a live session. Tests and `hack/qwenbench` use a three-line static resolver instead of the store.
- 2026-09-01 — An unreadable, undecodable, invalid or unbuildable state file is a startup failure; Cascade never silently falls back to `bootstrap`. With neither a state file nor a bootstrap the gateway starts empty, writes nothing, and refuses realtime connections until a default profile is configured.
- 2026-09-01 — The Admin metric is named `cascade.admin.config_writes{cascade.result}` (`ok|invalid|conflict|not_found|persist_error`) to match the repository's OTel naming; a Prometheus exporter renders it as `cascade_admin_config_writes_total`. Session spans and the `cascade.sessions.*` metrics gained `cascade.profile` / `cascade.asr` / `cascade.llm` / `cascade.tts` so a call can be attributed to the configuration that served it.
- 2026-09-01 — `internal/protocol`'s `TestProfileAcceptedItemsAndOverrides` was racy and unrelated to Phase 6 (it fails on the Phase 5 commit too): the rig sent a `conversation.item.create` carrying `previous_item_id: "sys1"` before the adapter had seen the `conversation.item.added` event that fills its id table, so the reference resolved to "does not exist" under load. The test now waits for that event first; no production code changed.
- 2026-09-01 — Phase 6 acceptance ran against the live Model Studio endpoints. `TestE2EQwenAdminProfile` (`-tags e2e`, `ALIYUN_API_KEY`) is the regression asset for the Admin path: an empty store refuses `/v1/realtime` with 503, the whole runtime configuration is created through `/admin/v1` with `api_key` left as `{env.ALIYUN_API_KEY}` (state file keeps the placeholder, `GET` returns `***`), a real voice turn runs on the resolved profile, `response.cancel` closes the qwen TTS and chat streams (`reason=cancelled`, 759 µs to `response.done`), an Admin write is invisible to the live session but takes effect on the next connection, and a restart from the state file rebuilds the same providers. `asr_language: "en"` is asserted through the transcript: without it the qwen ASR transcribed the English fixture into Spanish, which is the end-to-end proof that the profile field reaches `provider.ASRConfig`.
- 2026-09-01 — Measured after the Phase 6 refactor, unchanged from the Phase 5 baseline in `docs/qwen-latency.md`: `qwenbench -only e2e` speech end → first playable audio p50 1154 ms (baseline 1223 ms), commit → transcript 0.9–2.3 s across runs. `go test -tags qwenreal` passes end to end (LLM TTFT 241 ms, TTS first audio 303 ms, ASR final 216–320 ms after end of speech).
- 2026-09-01 — The Phase 4/5 real-provider e2e (`TestE2EVoiceTurnAndInterrupt`, deepgram + openai) also passes unchanged after Phase 6 (35.7 s, gpt-4o-mini). On a slow network path the providers dominated — LLM TTFT 6.09 s, TTS first audio 3.53 s, e2e 10.68 s — while the gateway itself added ~2 ms (commit → `response.created` −2 ms, last audio → `response.done` 1 ms). All three interrupt paths still cut in 1 ms: `response.done{cancelled}` 1 ms after `response.cancel`, the in-flight TTS or LLM stream closed with `reason=cancelled` 1 ms later, and the deepgram stream 1 ms after client disconnect. Turn-1 event order matches the Phase 2 profile exactly.
- 2026-09-01 — Phase 7 adds function calling. `session.tools` / `session.tool_choice` move from echoed-only to effective; the whole delta is folded into `docs/protocol-profile.md` (§2, §3, §5–§10) and `docs/protocol-profile-phase7-delta.md` is deleted. Every wire shape was transcribed from `openai-node` v7.8.0 `realtime.ts` rather than inferred.
- 2026-09-01 — Tool-call argument fragments are accumulated **inside each provider adapter**, which emits one complete `provider.LLMToolCall` chunk before `LLMDone`; `internal/session` never sees a partial call. That single boundary decision produces three visible consequences: `response.function_call_arguments.delta` is emitted once with the complete arguments, cancelling mid-arguments delivers no call at all (a documented GA deviation — GA emits `.done` with partial arguments), and a truncated generation (`finish_reason: length` / `content_filter`) delivers no call either, because the arguments are unusable.
- 2026-09-01 — `pipeToolCall` is the single delivery path from pipeline to actor: the actor commits the `function_call` item and emits its whole lifecycle the moment the call arrives, and `pipeLLMDone` does not carry a call. Two paths would mean two places that can create the item and an ordering question between them. A tool call is never written to the sentencer channel, so TTS can never speak JSON arguments — asserted in `TestTTSNeverReceivesToolArguments` and again on live providers in `TestE2EQwenToolCall`.
- 2026-09-01 — The assistant message output item is created lazily, on the first text delta (`ensureOutputItem`), instead of at pipeline start, so a call-only turn emits no empty message item. Verified empirically before adopting: the Phase 2–5 golden traces `text_turn`, `cancel_text` and `manual_commit` are byte-identical, because the added/part frames already sat immediately before the first delta. Only `errors.golden.jsonl` moved, and only on the two lines that had to move — `e5`'s param becomes `session.tools[0].name` and `e12`'s message now lists `function_call_output` as an accepted item type.
- 2026-09-01 — A tool call's wire `call_id` is minted by the protocol adapter (`call_` + 16 lowercase alphanumerics), not passed through from the LLM provider. Neither OpenAI's (`call_` + mixed case) nor DashScope's (`call_` + 24 hex) id matches the profile §9 format, and passing one through would leak a provider specific into the protocol layer. The provider's own id stays on `session.Item.CallID`, where it is the key that links a result back to its call in `messages()` replay; the adapter maps it to the wire id in both directions, so a `function_call_output` echoes the same `call_id` as its call.
- 2026-09-01 — `messages()` replays an assistant turn that spoke *and* called as **one** `provider.Message` (text plus `ToolCalls`), merging the message item with the `function_call` item that follows it, and a `function_call_output` as `{Role: RoleTool, ToolCallID, Content}`. The empty-text skip is applied only to message items: a no-argument call and an empty tool result are both legitimate and both carry no text.
- 2026-09-01 — `response.done()` becomes `llmDone && (textOnly || !spoke || (ttsDone && audioFlushed))`. A turn that produced no text has nothing to synthesize, so a call-only turn completes as soon as the LLM does; the TTS stage's late `pipeTTSDone` is filtered by the generation bump in `finish()`. A delivered `function_call` item closed its own lifecycle at delivery, so `finish()` only lists it in `response.done.output` — it is never re-emitted and never reopened by a cancel that arrived afterwards.
- 2026-09-01 — `tool_choice` is resolved in Cascade's session model (`config.Profile.ToolChoice`, default `"auto"`, projected into `SessionDefaults`) and captured onto the response at `createResponse`, so a `session.update` landing during the awaiting phase cannot change a generation already under way. The three tool fields reach a provider request only together with a non-empty `tools` array: OpenAI rejects `tool_choice` and `parallel_tool_calls` on a request that declares no tools, so sending them unconditionally would have broken every existing tool-less session. A profile may not force a specific function, because it declares no tools to force.
