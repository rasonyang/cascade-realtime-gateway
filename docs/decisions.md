# Decisions

One line per decision, newest last. Format: `YYYY-MM-DD — <decision> (<why>)`.

- 2026-09-01 — Replies to the user are in Chinese per the user's harness language setting; code, comments, docs, commits and logs stay English per `CLAUDE.md`.
- 2026-09-01 — `session_defaults.audio.input.transcription` uses the GA nullable-object shape (no `enabled` field); `null` disables `conversation.item.input_audio_transcription.*` events, an object enables them. The internal ASR always runs for the ASR → LLM pipeline regardless. Exact field subset is frozen in Phase 2 (`PROTOCOL-VERIFY`).
- 2026-09-01 — `session_defaults.audio.output.speed` is in config with default `1.0`, validated against the currently documented GA range `[0.25, 1.5]`; re-verified when the Phase 2 profile is frozen.
- 2026-09-01 — `turn_detection` validation is type-specific: `threshold` / `prefix_padding_ms` / `silence_duration_ms` only for `server_vad`, `eagerness` only for `semantic_vad`; mixed shapes are rejected. Under `semantic_vad` the acoustic VAD (Phase 1) uses the `server_vad` defaults since GA exposes no tuning fields there.
- 2026-09-01 — Config load order: read → `{env.X}` expansion on the generic JSON tree (error names the field path) → strict decode (`DisallowUnknownFields`) over `DefaultConfig()` → mode-specific `turn_detection` defaults → `Validate`. Absent field = default; `"turn_detection": null` = manual mode.
- 2026-09-01 — `config.Validate(known ProviderLookup)` takes an injected lookup so `internal/config` never imports `internal/provider`; a nil lookup skips provider-name existence checks (Phase 0 only, registry wired in Phase 1).
- 2026-09-01 — WebSocket library: `github.com/coder/websocket`; added only when a phase needs it (Phase 2/3).
- 2026-09-01 — Phase 0 `cmd/cascade` with a valid config logs an allowlisted, redacted summary and exits 0; the HTTP/WebSocket server arrives in Phase 3.
- 2026-09-01 — `session` imports `config` and uses `config.SessionDefaults` directly as its immutable session snapshot and the `EvSessionUpdated` payload; `session.update` patches are validated with the same `SessionDefaults.Validate` as the config file (brief §7: "saving a translation layer").
- 2026-09-01 — Non-incremental TTS providers are downgraded to one `Synthesize` per sentence inside the pipeline's TTS stage (not inside each provider adapter): zero interface changes, and per-sentence audio ranges are exact for tier-2 truncation. Sentences are synthesized sequentially with no lookahead; revisit after Phase 4 latency measurements.
- 2026-09-01 — Commands carry an opaque `Tag` (`session.Meta`) echoed on `EvError` so the protocol layer can back-reference the client `event_id`; `provider.Factory` takes `(apiKey, options)`.
- 2026-09-01 — Inbound audio and commands stay on separate bounded queues, but every posted item carries a sequence number and the actor restores arrival order across the two queues (`append→commit` and `clear→append` behave as sent). Without this, `select` fairness could commit before earlier appends were applied.
- 2026-09-01 — ASR Final ↔ item mapping: Finals accumulate since the last commit; the first Final (or EndOfTurn) after a commit completes the committed item with everything accumulated. Audio that arrives between commit and the provider's flush may be attributed to the wrong item; accepted approximation.
- 2026-09-01 — Raw user PCM is not retained after commit (the ASR stream already received it live). If the Phase 2 profile supports `conversation.item.retrieve` with audio, storage is added then.
- 2026-09-01 — A committed item whose transcript never arrives and has no response waiting on it stays `in_progress` indefinitely; v1 adds no timeout for that case.
- 2026-09-01 — Algorithm constants kept as named constants rather than config (rule 7 covers queues, caps and timeouts): VAD frame 20 ms, hysteresis exit = 0.6 × entry, threshold→RMS scale 0.1, sentencer minimum 6 runes plus a small abbreviation list, semantic_vad eagerness → extra silence high 400 / medium 800 / low 1500 ms (auto = medium).
- 2026-09-01 — Outbound event stall handling lives in the Phase 3 server writer (`client_write_timeout`), not in the actor: `emit` blocks on a full outbound queue until ctx is cancelled; `EvSessionClosed` delivery waits at most `client_write_timeout`.
- 2026-09-01 — `response.cancel` with no active response or a foreign `response_id` is a silent no-op internally; whether the wire layer returns an error is settled in the Phase 2 profile (`PROTOCOL-VERIFY`).
- 2026-09-01 — Text-only responses do not open TTS at all; `ttsDone`/`audioFlushed` are considered satisfied. `audioFlushed` is set together with `ttsDone` because deltas and the done fact travel the same ordered channel.
- 2026-09-01 — Protocol profile approved (`docs/protocol-profile.md` §10). Protocol validation errors use only the officially attested codes `invalid_event` / `invalid_value` with `message` + `param`; Cascade runtime errors are `server_error` with Cascade codes. `conversation.item.created` and `rate_limits.updated` are never emitted. `voice` follows GA and is locked after the first output audio delta (session-owned `audioEmitted` flag).
- 2026-09-01 — Committed audio items are reported `in_progress` until their ASR final arrives, then `conversation.item.done` (GA reports `completed` immediately and transcribes asynchronously); Cascade's transcript gates the LLM, so the deferred `done` is the honest projection.
- 2026-09-01 — `conversation.item.truncate` beyond the generated audio is an error (`invalid_value`, `param: audio_end_ms`), never a clamp; the §5.5 "no trimming at or beyond total" invariant now applies only to `audio_end_ms == total`.
- 2026-09-01 — `Item.ClientID` / `ItemSpec.ClientID` carry the client-supplied item id opaquely through the session so the protocol layer's id table is filled from events alone; `EvResponseCreated` carries the effective modalities / voice / max tokens / metadata so the response object is echoed without guessing.
- 2026-09-01 — Inbound protocol validation walks the raw JSON object with per-event allow-lists (`internal/protocol/decode.go`) instead of `DisallowUnknownFields` structs, so every rejection can name the dotted `param` path and beta fields get a pointed message. The adapter resolves wire ids to session refs before posting, so unknown `item_id` / `response_id` / `previous_item_id` never reach the actor.
- 2026-09-01 — Golden traces normalize server ids to `<prefix:n>` in first-seen order (fixed-length id regex so `param: "item_id"` is not mistaken for an id); audio/transcript interleaving is covered by the causal-invariant tests only, as the brief requires. Regenerate with `go test ./internal/protocol -run TestGolden -update`.
- 2026-09-01 — Phase 2 acceptance item "text-only conversation with the official GA SDK or websocat" is deferred to the start of Phase 3: it needs the WebSocket server, and adding `coder/websocket` for a throwaway harness would widen Phase 2 scope.
- 2026-09-01 — Phase 3 server: one goroutine trio per connection (handler read loop, event pump, single writer). The read loop uses its own context so a session-context cancellation (timeout, shutdown, fatal error) lets the writer send queued frames and the close frame before reads stop; the writer's per-frame timeout is `client_write_timeout` from a background context for the same reason. WebSocket close codes: 1000 (client close / `session_timeout` reason), 1001 `shutting_down`, 1011 with the Cascade code for fatal errors, 1009 by the library when `client_max_message_bytes` is exceeded.
- 2026-09-01 — `websocket.Accept` skips the Origin check (`InsecureSkipVerify`): the endpoint is gated by the Bearer token, which browsers cannot attach cross-origin, so an Origin allow-list would only break non-browser clients.
- 2026-09-01 — `max_sessions` is enforced before the upgrade with HTTP 503 (JSON `server_error` body); a rejected connection never creates a session. `session_timeout` bounds the session context; the session reports `CloseSessionTimeout` from the deadline cause.
- 2026-09-01 — No shutdown timeout config: `Server.Shutdown` ends every session and waits; session cleanup is bounded by `client_write_timeout` and the close handshake by the library's 5 s, so `main` passes `2 × client_write_timeout` as the shutdown deadline.
- 2026-09-01 — Cascade serves plain `ws://`; TLS belongs to a terminator in front of it. The official `openai-node` v7.8.0 `OpenAIRealtimeWS` client refuses anything but `wss:`, so the manual Phase 2/3 acceptance ran through a throwaway self-signed TLS reverse proxy (scratchpad only) with `rejectUnauthorized: false`; it completed a text conversation with no beta header. The deferred Phase 2 acceptance item is therefore closed.
- 2026-09-01 — Phase 4 providers: `openai` LLM (Chat Completions SSE, `stream_options.include_usage`, `max_completion_tokens`, instructions as a `system` message), `openai` TTS (`/audio/speech` with `response_format: "pcm"` = 24 kHz 16-bit LE, one request per sentence, `IncrementalText=false`), `deepgram` ASR (`/v1/listen` linear16/24000, `interim_results`, `punctuate`, `endpointing`, `utterance_end_ms`; `Authorization: Token`). Per-provider timeouts live in the provider `options` block (`request_timeout`, `stream_idle_timeout`, `connect_timeout`, `finalize_timeout`, `keepalive_interval`) with defaults in each package.
- 2026-09-01 — Deepgram documents that the `from_finalize` result after `Finalize` is not guaranteed; the adapter synthesizes `EndOfTurn` after `finalize_timeout` (default 1.5 s) so the ASRStream contract ("Finalize guarantees a Final or EndOfTurn") holds. Empty `is_final` results are ignored unless they are the `from_finalize` reply.
- 2026-09-01 — Providers report lifecycle facts (`… stream opened/closed`, `reason`, `lifetime_ms`) at Debug level through `slog.Default()`; `cmd/cascade` installs the redacting logger as default. The e2e test captures these records to prove interrupt cleanup timing.
- 2026-09-01 — Real-provider e2e (`-tags e2e`, `internal/server/e2e_test.go`) synthesizes the user's speech with the real OpenAI TTS, runs one server_vad turn, then two interrupts (at first audio delta → TTS in flight; at first transcript delta → LLM in flight) and a disconnect. Measured 2026-09-01 with gpt-5-nano: commit→ASR final 0.9 s; tts/llm/deepgram streams closed 0–1 ms after cancel/disconnect. A pause inside one utterance splits the turn under server VAD (as with OpenAI), so the e2e widens `silence_duration_ms` to 800 and tolerates an intermediate cancelled response.
- 2026-09-01 — The commit → ASR Final latency is measured in the session (`transcript final` log with `commit_to_final_ms`); Phase 5 exports it as a metric.
- 2026-09-01 — Phase 5 observability: OTLP/HTTP exporters (`observability.otel_endpoint` = `host:port`, insecure; empty = no-op providers so session code never branches). Spans: `session` → `response` → `llm` / `tts`; the pipeline ctx derives from the response span so provider work is attributed without any provider instrumentation; no frame-level spans. Metrics (histograms in ms): `cascade.asr.first_transcript_ms` (speech start → first partial), `cascade.asr.final_transcript_ms` (speech stop → final), `cascade.asr.commit_to_final_ms`, `cascade.llm.ttft_ms` (pipeline start → first text delta), `cascade.tts.first_audio_ms` (first sentence handed to TTS → first audio delta, via the internal `pipeTTSStart` fact), `cascade.e2e_ms` (commit — or response.create for text turns — → first output delta), `cascade.interrupt_ms` (speech start / cancel command → response.done{cancelled}); counters `cascade.provider.errors{cascade.provider}`, `cascade.sessions.ended{cascade.reason}`, up-down `cascade.sessions.active`. In manual mode the commit stands in for speech start/stop.
- 2026-09-01 — Metric export interval is the SDK default (60 s) and spans are batched; `cmd/cascade` flushes both on shutdown, bounded by `client_write_timeout`. No new config fields.
- 2026-09-01 — Frame-level logging stays off: nothing logs per audio frame or per delta; provider lifecycle logs are Debug-level, one per stream.
- 2026-09-01 — `providers.llm.options.reasoning_effort` (openai) is passed through verbatim and omitted when empty: OpenAI documents that supported values vary by model (verified: `gpt-5-nano` rejects `"none"` and accepts `"minimal"`; non-reasoning models reject the field), so Cascade sets no default and validates nothing beyond "string".
- 2026-09-01 — `hack/sdkcheck/` keeps the official-SDK manual check (node scripts, mock config, self-signed TLS terminator in the main module); binaries, `node_modules/`, logs and pids are git-ignored.
